# 数学辅导方案调研与落地记录

日期：2026-10-29

## 调研来源

- [gpoesia/socratic-tutor](https://github.com/gpoesia/socratic-tutor)：将数学题描述为明确状态、可执行动作和完成条件的教学领域。借鉴：答案核验由确定性逻辑承担，不只依赖生成模型。
- [hwl668/Scientific-learning-skills-](https://github.com/hwl668/Scientific-learning-skills-) 的 problem-solving skill：按题型、关键条件、模型、分步求解和变式训练推进。借鉴：针对具体卡点选教学动作，并区分测试输入与模型真实输出。
- [Bhala-Srinivash/agent-tutor-skill](https://github.com/Bhala-Srinivash/agent-tutor-skill)：Explain、Example、Check、Evaluate、Practice 循环，并用学习者实际作答作为掌握证据。借鉴：讲过答案不等于独立掌握，“我试试”也不算答对。
- [rocklogic11/k12-math-tutor](https://github.com/rocklogic11/k12-math-tutor)：公开 K12 数学辅导 Skill。该 Skill 面向完整解题讲解，而非当前产品的多轮引导，因此只参考显式分步和计算复核，没有照搬长篇回答模板。

这些是开源项目作者的设计，并非相同条件下的对照实验或已验证教学效果。各项目许可证不同；本项目没有复制其代码或提示词全文，只落实通用流程原则。

## 本次改进

- 针对正方形面积、分数加减、千米换米、路程和平均分增加严格题型匹配及精确算式核验。中间每个等式、最终值、最简分数和单位都需正确；题目形态不匹配时回到常规辅导流程。
- 把“我试试 / 我再想想 / 等一下”识别为等待，不作为理解或通过的证据。连续卡住时先换具体小步骤；仍无法推进时提供讲解，条件不足则明确说明缺项。
- 对近期回复做规范化相似度检查。检测到重复时最多重写一次，并约束改写不能改变阶段、泄露答案或带入新数字；不合格时换一个小提示。
- 进入新教学阶段时重置本阶段防循环计数，避免前一阶段的重复状态影响后续过程。

## 测试记录

- 修复前真实本地模型：6 项场景仅 1 项通过；正确答案后仍追问，且等待用语最终被误归档为独立掌握。原始记录保存在 `output/repetition-2026-10-29/model-before/` 与 `output/repetition-2026-10-29/model-after/`，失败过程保留供比较。
- 最终全项目回归：389 项通过（1项第三方弃用提示），结果见 `output/repetition-2026-10-29/full-suite-final.xml`。扩大回归曾发现正常读题进度被误识别为重复、等待用语被模型错误表扬；问题已修复并通过全量重测，失败报告保留。
- 最终真实本地模型复测：6/6 通过。正方形、分数、单位换算、路程、平均数五题都以本地精确核验结束；缺少组数的题在重复等待后明确指出条件不足，归档为“看过讲解”而非独立掌握。最终完整对话和 JSON 在 `output/repetition-2026-10-29/model-verified/`，包含没有错误表扬等待用语的检查。
- 正常网站服务中的多知识点测试：12/12 通过，涵盖11个知识点，档案编号47-58。追加的等待循环复测编号60通过，归档为 `整除`、“看过讲解”；编号59保留了发现“等待”被错误肯定的失败记录，修复后复测未再出现该情况。学习档案浏览器检查确认共60条记录，截图和检查结果见 `output/repetition-2026-10-29/archive-browser-final/`。
- 注意：该实测的教师回复来自本地模型；答案核验和防循环控制由产品规则负责。测试通过只覆盖这些脚本场景，不能据此声称所有自由对话都绝不重复。

## 适用边界

不能保证对所有自然语言和任意新题型绝不出现语义重复。严格自动判分仅用于完整匹配的题目模板；其他题目通过近期历史提示、重复检测、最大轮数和讲解兜底降低循环风险。新增可核验题型时应同时增加正确答案、错误答案和真实模型测试。
