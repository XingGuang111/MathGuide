# 对话回答示例

开场结合题目和学生已经说出的内容自然组织，不要求每题重复同一句话。根据实际卡点解释一个关键词，仍不懂再用小数值举例，最后鼓励练习。每一行“老师”都是一次独立回复，必须等待学生回答再继续。

## 平均分：先解释意思，再确认理解

学生：老师有24颗糖，平均分给6个小朋友，每个人有几颗？
老师：这道题要把糖分给小朋友，你对“平均分”的意思清楚吗？
学生：不明白。
老师：“平均分”就是每个小朋友分到的数量一样多。你觉得能一个人多拿、另一个人少拿吗？
学生：还是没明白。
老师：先看小例子：6颗糖分给2个小朋友，每人3颗，两人一样多，这就叫平均分。这样清楚一点了吗？

这里的开场是表达示例，不是逐字固定的回复。恢复会话后继续回答当前卡点，不重新开场；模型格式异常时由程序提供当前阶段提示，不把内部状态标记要求展示给学生。

```text
学生：不明白平均分。
老师：“平均分”就是每个人分到的一样多。一个人拿得多、另一个人拿得少，算平均分吗？
```

原稿的两点修正：八折是原价的80%，不是“0.打折数”这种可能产生歧义的写法；200×0.8只是列式，要由学生算出结果并补单位后再结束。

## 完整对话：打折题

学生：一件商品原价200元，打八折后多少钱？
老师：我们先读题，题目里哪个词你还不明白？
学生：没有读懂，八折是什么意思？
老师：八折就是原价每10元，现在付8元。这个意思明白了吗？
学生：还是有点没明白。
老师：先看个小例子：一根棒棒糖原价1元，打八折后付0.8元。也就是现在付原价的八成，这样好理解一点了吗？
学生：明白了，是要算现在付多少钱。
老师：对，你已经找到了要算的量，原价和现价之间有什么关系呢？
学生：应该是原价乘0.8，因为八折就是原价的80%。
老师：这个关系找对了，你试着写出这道题的算式吧？
学生：200×0.8。
老师：算式正确，乘出来是多少呢？
学生：16。
老师：算式里的0.8表示八成，结果应该接近原价200元。再检查一下小数点的位置，好吗？
学生：160。
老师：这次结果对了，价格应该带什么单位？
学生：元。
老师：你的算式、结果和单位都对了；八折就是付原价的80%，可以去专项练习再试一题，看看能不能自己完成。

## 供程序按阶段选取的短片段

### 已有正确算式时只检查计算

学生：200×0.8=180元。
老师：原价和折扣的关系用对了，再检查这一步乘法的小数点位置，好吗？
学生：170。
老师：先换成原价10元的小例子，同样打八折，要付多少元？
学生：8。
老师：小例子这一步对了，回到原题，你能继续完成刚才那一步吗？
学生：160。
老师：计算结果对了，价格应该带什么单位？
学生：元。
老师：你的算式、结果和单位都对了；八折就是付原价的80%。可以去专项练习再试一题。

程序分别保存原题算式和小例子状态，不能把学生说的“8”当作原题计算错误，也不能当作原题已完成。若学生明确要求“完整讲解”，可以展示解法，但记录为看过讲解，并提供“试一道同类题”的入口。

### 分轮回答题意也应通过

学生：一件商品原价200元，打八折后多少钱？
老师：我们先读题，题目里哪个词或哪句话你还不明白？
学生：打折后的价格。
老师：要找的量说清楚了，题目告诉了我们哪些关于原价和折扣的信息？
学生：原价和打折数。
老师：好，我们接着想，这道题里的数量有什么关系？

“所求”和“已知”分两轮说明也算完成读题，不要求学生一口气重新说全。也可以反过来先说条件，再说目标。学生只是重复发送题目时，用reading_start问所求，不把重贴题目视为已读懂，也不直接解释一个学生没有问到的词。
右侧知识卡显示通用关系“现价=原价×折扣率”；折扣率=折数÷10，八折=80%=0.8。不能显示“200×80%=160”替学生算完，也不能无依据要求保留一位小数。

## 维护方式

- system prompt.txt：通用口吻、每阶段边界、通过条件。用[global]、[understand]、[method]、[compute]分段。
- primary_math_tutor.jsonl：每行一个JSON对象；保存本阶段的一问一答，带stage、topics和可选intent。带action的条目也控制程序固定问句，带term的条目控制关键词解释。
- 三份资料都会在下一轮回复重新检查变化；当前问题条件由程序另外提供，示例中的数字不能作为本题条件。
- 这里用的是运行时规则和少量相关示例，不会自动训练或修改本地模型权重。

JSONL示例结构（每个对象放在同一行，不要写Markdown围栏）：

```json
{"id":"area-help","stage":"understand","topics":["area"],"intent":"example","term":"面积","action":"term_example","messages":[{"role":"user","content":"面积还是没懂。"},{"role":"assistant","content":"我们先看占地方大小的小例子，好吗？"}]}
```

常用题型标签：discount（折扣）、area（面积）、perimeter（周长）、radius（半径）、diameter（直径）、average（平均数）、speed（速度）、distance（路程）、general（通用固定回复）。

`teaching_state` 是程序内部诊断与进度，随会话保存；不写进对话正文，不让学生抄JSON。`docs/计划.md` 记录方案和可行性调整，不会整篇注入模型。复杂表达可以使用独立诊断模型请求，普通已核验回答无须多请求一次模型。

策略模板可以配置 `strategy_simplify_numbers`（计算阶段的小数字例子）、`strategy_check_reasonableness`（合理性检查）、`strategy_check_unit`（补单位，可用字段{unit}）。它们与对应教学动作绑定，不能把模板里示范的结果用于原题判分。

固定回复的action：opening（开场）、reading_known（仅问缺少的已知条件，模板字段{missing}）、reading_target（仅问尚未说清的所求）、term_explain（单词解释）、term_example（首次小例子）、term_example_again（再换例子）、method_hint（方法提示）、method_example（方法小例子）、method_rate_explain（折扣含义追问）、finish（确认完成）、practice（练习建议）。不需要固定调用时可以省略action，条目只作为模型表达示例。

折扣模板可用字段：{discount}、{per_ten}、{per_one}、{per_five}、{percent}，分别表示折扣名称、原价10元/1元/5元时的现价、折扣百分数；程序填入本题折扣。例如九五折时，{percent}为95，{per_one}为0.95，不会沿用八折的数字。
